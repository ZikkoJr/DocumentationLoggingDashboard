Documentation Logging Dashboard - Excel Logs and V1 Compatibility Checklist
============================================================================

Use this checklist for manual UI testing after the build and automated
regression harness pass. The filename is retained for continuity with the V1
release checklist. Current submissions use Excel; historical V1 TXT files
remain valid read-only records.

Startup
-------

[ ] Start the app.
[ ] Confirm the dashboard opens without errors.
[ ] Confirm the current documentation root folder path is visible.
[ ] Confirm the existing selector contains Debugging Log, Script Editing Log,
    and Script Creation Log.
[ ] Confirm the privacy reminder is visible:
    Reminder: Do not enter guest names, emails, payment data, credentials, or
    full hotel files into logs. Use ticket IDs, hotel IDs, script names, and
    summarized issues instead.

Running workbook selection
--------------------------

[ ] Select Debugging Log and confirm the active Running-workbook selector lists
    only compatible Debugging Running `.xlsx` files.
[ ] Select Script Editing Log and confirm the selector changes to compatible
    Editing Running files.
[ ] Select Script Creation Log and confirm the selector changes to compatible
    Creation Running files.
[ ] Use Create New Log File for each type and confirm `.xlsx` is appended when
    omitted and the created workbook is immediately selected.
[ ] Confirm an existing filename is not overwritten.
[ ] Confirm rooted paths, path separators/traversal, unsupported extensions,
    invalid names, and reserved Windows names are rejected.
[ ] Close and reopen the app and confirm each type remembers its own last-used
    Running workbook.
[ ] Rename or remove a remembered workbook in a synthetic test root and confirm
    the app remains usable and permits another selection/creation.

Preview each log type
---------------------

[ ] Select Debugging Log.
[ ] Search for and select a Hotel by Hotel ID.
[ ] Confirm canonical Hotel Name, Hotel ID, and PMS are shown read-only.
[ ] Fill Error Shown On Ticket, Root Cause, and Fix Applied.
[ ] Leave Created By and Notes / Follow-up blank.
[ ] Click Preview Entry.
[ ] Confirm the preview includes a candidate DEBUG-yyyyMMdd-### Log ID.
[ ] Confirm blank optional fields show N/A.

[ ] Select Script Editing Log.
[ ] Enter one or more manual Hotel IDs using comma, semicolon, or multiple lines.
[ ] Fill Script Name, Reason For Edit, and Changes Made.
[ ] Leave Created By and Notes / Follow-up blank.
[ ] Click Preview Entry.
[ ] Confirm the preview includes a candidate EDIT-yyyyMMdd-### Log ID.
[ ] Confirm the normalized Hotel IDs retain leading zeroes and first-entered
    order and use `ID1; ID2; ID3` representation.
[ ] Confirm blank optional fields show N/A.

[ ] Select Script Creation Log.
[ ] Enter one or more manual Hotel IDs.
[ ] Fill Script Name, Reason For Creation, and Script Purpose / What It Does.
[ ] Leave Created By and Notes / Follow-up blank.
[ ] Click Preview Entry.
[ ] Confirm the preview includes a candidate CREATE-yyyyMMdd-### Log ID.
[ ] Confirm blank optional fields show N/A.

Required-field and metadata validation
--------------------------------------

[ ] For Debugging, clear each of Hotel selection, Error Shown On Ticket, Root
    Cause, and Fix Applied in turn and confirm Preview/Submit reports it.
[ ] For Editing, clear each of Hotel ID(s), Script Name, Reason For Edit, and
    Changes Made in turn and confirm Preview/Submit reports it.
[ ] For Creation, clear each of Hotel ID(s), Script Name, Reason For Creation,
    and Script Purpose / What It Does in turn and confirm Preview/Submit reports
    it.
[ ] Enter one unknown Hotel ID and confirm the full Editing/Creation save is
    blocked and identifies the ID.
[ ] Enter mixed valid and invalid IDs and confirm no partial event is written.
[ ] Enter duplicate IDs and confirm they normalize once in first-entered order.
[ ] Change/remove a selected Debugging Hotel's metadata before Submit and confirm
    fresh resolution blocks the stale selection and requires refresh/reselection.

Submit and route entries
------------------------

[ ] Submit one valid Debugging event.
[ ] Confirm exactly one row is added to the selected Debugging Running workbook.
[ ] Confirm exactly one row is added to the selected Hotel's
    DebuggingLogHistory.xlsx.
[ ] Confirm exactly one row is added to the selected canonical PMS's
    DebuggingLogHistory.xlsx.
[ ] Confirm all copies have identical Log ID, Date/Time, canonical metadata,
    business values, Created By, and Notes / Follow-up.

[ ] Submit one Editing event for two Hotels on the same PMS.
[ ] Confirm Running is updated once, each Hotel history once, and the shared PMS
    history once.
[ ] Submit one Editing event for Hotels on different PMS systems and confirm each
    unique PMS history is updated once.
[ ] Confirm Script Name, Reason For Edit, Changes Made, and the full normalized
    Hotel-ID list are identical in every copy.

[ ] Repeat the same same-PMS and different-PMS routing checks for Script Creation.
[ ] Confirm Script Name, Reason For Creation, Script Purpose / What It Does, and
    the full normalized Hotel-ID list are identical in every copy.
[ ] Confirm a successful Submit clears draft fields but retains the selected
    type's Running-workbook preference.

Workbook files and schemas
--------------------------

[ ] Confirm the selected root contains DebuggingLogs/Running,
    ScriptEditingLogs/Running, ScriptCreationLogs/Running, and Index.
[ ] Confirm Running workbooks remain direct children of their assigned Running
    folder.
[ ] Confirm Hotel histories live only under QAReports/ByHotel/<canonical folder>.
[ ] Confirm PMS histories live only under QAReports/ByPMS/<canonical folder>.
[ ] Confirm row 1 is the human-readable scope title, row 2 is blank, row 3 is the
    exact header row, and row 4 onward contains data.
[ ] Confirm each workbook uses a real filtered Excel Table and freezes through
    the header row.
[ ] Confirm Date/Time is a real Excel date/time and Log ID/Hotel IDs are text.
[ ] Confirm long text wraps and no cells inside the data table are merged.
[ ] Confirm `Log Type` is not a table column.
[ ] Confirm hidden `__DLD_Metadata` identifies schema version 1, log type, scope,
    and scope ID.
[ ] Confirm an existing wrong-type, wrong-scope, changed-header, missing-metadata,
    unsupported-version, or corrupt workbook is rejected without alteration.

Historical V1 TXT compatibility
-------------------------------

[ ] In an isolated root, place representative historical daily files directly
    under DebuggingLogs, ScriptEditingLogs, and ScriptCreationLogs.
[ ] Record their hashes/bytes before submitting a new Excel event.
[ ] Submit new Debugging, Editing, and Creation Excel events.
[ ] Confirm every historical TXT file remains byte-for-byte unchanged.
[ ] Confirm no new daily TXT file is created and no existing TXT file receives a
    new entry.
[ ] Confirm historical TXT files were not moved, renamed, deleted, or migrated.
[ ] Confirm Open Logs Folder still permits operators to reach historical TXT.

LogIndex.txt and sequence state
------------------------------

[ ] Confirm Index/LogIndex.txt exists.
[ ] Confirm each logical event adds exactly one pipe-separated index line,
    regardless of its Hotel/PMS workbook-copy count.
[ ] Confirm the Debugging line uses Hotel: {Hotel Name} / {Hotel ID} and
    PMS: {PMS}.
[ ] Confirm Editing and Creation lines use Script: {Script Name} and
    Hotel IDs: {canonical list}.
[ ] Confirm each new Saved File field points to the selected Running `.xlsx`, not
    a Hotel/PMS history workbook.
[ ] Confirm historical index lines and their daily TXT paths remain unchanged.
[ ] Confirm no documentation entry is added to QAReports/Index/QAReportIndex.txt.
[ ] Confirm `documentation-log-sequences.json` is versioned and root-scoped under
    Index.
[ ] Confirm first and second events of a day use 001 and 002 for each type.
[ ] Confirm switching Running workbooks, creating a new Running workbook, and
    restarting the app do not reset the sequence.
[ ] Seed the current day's legacy TXT and LogIndex with different valid sequence
    values and confirm the next ID is above the highest applicable value.
[ ] Confirm Hotel/PMS copies do not consume additional IDs.
[ ] Confirm Preview does not reserve or increment sequence state.

Locking, transaction, and reentrancy
-----------------------------------

[ ] Open the selected Running workbook in Excel and confirm Submit reports a
    friendly unavailable message and commits nothing.
[ ] Repeat with one required Hotel history workbook open.
[ ] Repeat with one required PMS history workbook open.
[ ] Simulate an index or sequence-state failure and confirm no success message
    and no ordinary partial event remains.
[ ] Simulate a source change between staging and commit and confirm it is detected
    rather than silently overwritten.
[ ] Confirm ordinary commit failure restores already replaced files and removes
    newly committed files.
[ ] Where rollback itself is forced to fail, confirm the app identifies every
    manual-review path and does not claim restoration or success.
[ ] Confirm normal success/failure cleanup leaves no staging or backup residue.
[ ] Double-click Submit and confirm the save/reentrancy guard creates one event.

Switching types and open actions
-------------------------------

[ ] Enter a Debugging draft, switch to Editing, and confirm Debugging Hotel and
    business state does not leak into Editing.
[ ] Enter Editing Hotel IDs/business values, switch to Creation, and confirm they
    do not leak into Creation.
[ ] Switch repeatedly and confirm controls and click handlers do not duplicate.
[ ] Click Open Selected Log Workbook and confirm the selected Running workbook
    opens.
[ ] Remove/unavailable the selected workbook and confirm a friendly message is
    shown rather than a crash.
[ ] Click Open Logs Folder and confirm the current documentation root opens.
[ ] Click Open Log Index and confirm LogIndex.txt opens or a friendly missing
    message appears.

Folder settings
---------------

[ ] Click Change Logs Folder and select a new isolated test root.
[ ] Confirm the displayed root, metadata, Running choices, and root-scoped
    preferences refresh.
[ ] Submit a new event and confirm it is written only beneath the new root.
[ ] Confirm changing the root does not move old TXT or Excel files.
[ ] Click Reset to Default Folder and confirm the displayed root and choices
    refresh to the default DocumentationLogs location.

Quick QA and Detailed QA isolation
----------------------------------

[ ] Run the approved Quick QA regressions and confirm Surface workbook schema,
    remembered Surface workbook, Hotel history, findings/status, formatting, and
    transaction behavior are unchanged.
[ ] Run the approved Detailed QA regressions and confirm PDF output, paired
    Hotel/PMS save, Detailed index, File ID, warnings, strategy logic, findings,
    and statistics are unchanged.
[ ] Confirm documentation workbook preferences do not modify
    quick-qa-settings.json.
[ ] Confirm documentation Log IDs/index remain separate from Detailed QA File ID
    and QAReportIndex.txt.

Privacy
-------

[ ] Confirm testers know not to enter guest names, guest emails, payment data,
    credentials, confirmation-level PII, copied raw rows, or full hotel files.
[ ] Use only ticket IDs, Hotel IDs, script names, and summarized operational
    issues in test entries.

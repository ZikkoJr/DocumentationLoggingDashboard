Development publish only
------------------------

From the repository root, run:

powershell -ExecutionPolicy Bypass -File .\publish-windows.ps1

The script publishes the app for Windows x64 using Release configuration,
self-contained output, and single-file publishing. Its PublishedApp output is a
development location and is not the immutable V2 production candidate.

The fixed development output directory is not automatically a clean-room
inventory. For release evidence, also publish to a new empty temporary folder
with the equivalent dotnet publish command and inspect only that fresh output.

QA storage
----------

Detailed QA Report continues to create paired Hotel/PMS PDFs and
QAReports\Index\QAReportIndex.txt. New Detailed reports require text File ID,
but File ID does not change the PDF filename or Hotel ID + File Month overwrite
identity.

Quick QA writes one logical event to both a selected client workbook and Hotel
history:

DocumentationLogs\QAReports\SurfaceQA\<selected workbook>.xlsx
DocumentationLogs\QAReports\ByHotel\<canonical hotel>\QuickQAHistory.xlsx

The selected documentation root replaces DocumentationLogs when configured.
Quick QA does not create a PDF, PMS history, or Detailed index entry. Surface
workbooks are append-only through the app, and the saved last-used preference
contains only a direct-child filename under QAReports\SurfaceQA.

If a Surface or Hotel history workbook is open in Excel or otherwise
unavailable, close it and retry. A failure must not report success or leave an
ordinary one-sided Quick event. Back up the operational documentation root
before first post-pilot use.

Changing the logs folder
------------------------

Inside the dashboard, use Change Logs Folder to select a different writable
folder for future logs. The dashboard creates the expected folder structure in
the selected location. Existing logs are not moved automatically.

Use Reset to Default Folder to return to the DocumentationLogs folder beside the
published app.

Settings files
--------------

appsettings.json is included in the publish output and provides the default
DocumentationLogs setting.

user-settings.json is not included by default. The app creates it at runtime
beside the executable when the logs folder is changed or reset from inside the
dashboard.

Writable folder warning
-----------------------

Do not place the published app in protected folders such as C:\Program Files\
unless settings and logs are configured to a writable location. If the app is in
a protected folder, Windows may block writing user-settings.json or local logs
beside the executable.

Privacy reminder
----------------

Avoid entering guest names, emails, payment data, credentials, or full hotel
files into logs, findings, or Summary. Do not copy reservation-level PII or raw
rows. Use ticket IDs, hotel IDs, script names, and field/check-level summaries.
